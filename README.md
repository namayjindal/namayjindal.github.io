# namay.xyz — risograph softboard

Personal site for Namay Jindal. Static, served by GitHub Pages from this repo
(`CNAME` → namay.xyz). The homepage is a Risograph print of the softboard that
hung in his room back home: mustard cork, pinned notes, prints and badges.
Hovering a note lifts it off its shadow; clicking one opens a section.

Everything you see is generated by `riso/generate.py`. There is no design file,
no image editor, and no framework. Colour and texture come out of the ink model,
not out of CSS.

```
open index.html via any static server, e.g.
  python3 -m http.server 8000
```

### Regenerating the artwork

```sh
cd riso
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python generate.py all          # -> out/board.png and out/layers/
```

Then publish the layers to the site (PNG → WebP keeps the page around 2.5 MB
instead of 8.6 MB):

```sh
cd ..
cp riso/content.json assets/riso/content.json
riso/.venv/bin/python - <<'PY'
import json, pathlib
from PIL import Image
src, dst = pathlib.Path("riso/out/layers"), pathlib.Path("assets/riso")
for f in src.glob("*.png"):
    if f.stem == "_tooth": continue          # the site uses tooth-tile.webp instead
    Image.open(f).save(dst / f"{f.stem}.webp", "WEBP",
                       quality=72 if f.stem == "board" else 86, method=6)
m = json.loads((src / "manifest.json").read_text()); m["ext"] = "webp"
(dst / "manifest.json").write_text(json.dumps(m, indent=1))
PY
```

`assets/riso/highlight.webp` and `assets/riso/tooth-tile.webp` are one-off plates
(the bar behind the wordmark, and the tiling paper grain). They are not produced by
`generate.py all`; leave them alone unless you are changing those two things.

## 2. How the riso look is faked

Four mechanisms, all in `generate.py`. Internalise these before editing anything.

1. **Spot inks, multiplied.** Every colour is one of the real Risograph inks in
   `INK` — Yellow, Sunflower, Orange, Bright Red, Fluorescent Pink, Purple, Blue,
   Lake, Aqua, Teal, Green, Mint, Brown, Black. Ink is a coverage map from 0 to 1,
   composited multiply over cream paper, which is how translucent ink behaves.
   Because multiply can only darken, a shape that should read as *bare paper* is
   made by **knockout**: `subtract(wash, shape)`. The white rings in the watercolour
   and the cream slivers on the notes are knockouts, not white paint.

2. **Grain.** Three noise fields multiply into every layer: per-pixel speckle, a
   ~1px mottle, and a ~6px blurred field for uneven roller pressure. Pixels above
   0.985 on the fine field drop to 25%, faking spots where ink skipped.

3. **Misregistration.** Every ink pass is shifted 2 to 5 px in its own direction.
   On a note, the coloured ink is shifted *inside* its paper silhouette, which is
   what leaves the cream edge. This is the single most riso cue in the image.
   Do not align things.

4. **Halftone.** Tonal areas — the cork tooth, every drop shadow, the prints —
   are a rotated dot screen whose dot size wobbles across the sheet, not a flat fill.
   The mustard cork is Sunflower + a Green dot screen + a fine Brown screen. That
   combination is what moved it from "flat green" to something matching the photo.

### Paper objects vs ink layers

A note is a piece of paper sitting *on* the board, not ink printed onto it. So
elements come in two kinds, and `manifest.json` records which:

- **substrate elements** (`blend: "normal"`) — notes, prints, cards, badges, the
  board. Opaque: cream paper plus ink passes, alpha = the paper silhouette.
  Lifting one on hover reveals cork underneath, which is the point.
- **ink layers** (`blend: "multiply"`) — shadows, and the baked left-hand type.
  RGB is the un-premultiplied ink colour and alpha is coverage, so the browser's
  `mix-blend-mode: multiply` reproduces the same maths as the Python compositor.

`board.js` skips the `type`, `type-accent` and `logo` elements: the left column is
live HTML text so it stays selectable, responsive and accessible. The logo is
served as its own posterised image.

## 3. Editing the board

**Text and sections** live in `riso/content.json`. Each note has geometry
(`x`, `y`, `w`, `h`, `rot`), an `ink`, the handwritten `title` and `lines` that get
baked into the image, and the `heading` + `body` that the panel shows as live HTML.
Change the copy, re-run `generate.py`, re-publish the WebP layers.

**Most of the body copy is still marked PLACEHOLDER.** That is the next job.

`manifesto_words` is the hand-lettered roadtrip page, transcribed from the real
board. Capitalised words get their own ink; the type auto-shrinks to fit the page.

**Decorative pieces** (Paris print, rings watercolour, abstract painting, the New
York card, framed photo, washi tape, pink pad) are drawn in `decor()`. The badge
cluster is `badges()`. Both are plain coordinates and drawing lambdas.

**Adding a clickable note:** add an entry to `content.json` with
`"kind": "note"`, re-run, re-publish. `board.js` picks it up from the manifest's
`hover` field and adds it to the jump nav automatically. Nothing else to wire.

## 4. Rules

- Colour and texture are the point. Everything visual goes through `generate.py`
  or reproduces those four mechanisms. No CSS gradients, no `box-shadow`, no flat
  vector colour, no anti-riso "polish".
- Only real Risograph inks. If you need another, take it from a real riso chart
  and name it properly in `INK`.
- Misregistration stays. Grain stays. Knockouts stay.
- No frameworks and no bundler. A Python generator and static HTML/CSS/JS.
- Keep `generate.py` readable and comment the *why*: Namay wants to be able to
  explain this design to someone else without reading the code.

## 5. Known gaps

- Section copy is placeholder except `about`.
- The old sub-pages under `html/` still use the previous design and are not linked
  from the homepage. Either port them onto the riso paper or delete them.
- `board.webp` is ~1.2 MB, most of the page weight. If that matters, cut the cork
  into a smaller tiling patch instead of one full-board plate.
- Handwriting is Caveat, not Namay's actual hand. Scanning his lettering off
  `riso/reference/softboard_home.jpg` into a font would be a real upgrade.
- No `prefers-color-scheme: dark` treatment. A riso print arguably should not have
  one, but that is a decision, not an oversight.
